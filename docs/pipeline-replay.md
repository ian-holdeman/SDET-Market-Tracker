## Selection, trust and evidence

GET /api/test-pipeline returns a validated v2 envelope separating latest-nightly verification, run outcome, job evidence, browser evidence, any newer active attempt, and optional older archived replay. An archive never replaces the latest-nightly failure/unavailability notice. Browser counts remain browser-project cases; job success and artifact upload do not establish all-suite case success.

server/nightly-pipeline.ts queries only the configured Application baseline workflow with event=schedule and the trusted branch. It validates repository and head repository, branch, workflow path/ID, empty PR association when supplied, commit, run number/ID and attempt. It orders run identity before attempt, so a late rerun of an older run cannot outrank a newer night. Same-SHA nights remain distinct. An active rerun retrieves its prior completed attempt explicitly; failed-jobs-only reruns never borrow older jobs or browser cases.

Discovery reads at most five pages of five runs and at most ten exact attempts, under one ten-second GitHub request deadline. Metadata responses are capped at 300 KB. Search exhaustion is unavailable, not a guessed older success. Exact-attempt job metadata is independent of exact-attempt sanitized artifacts. Missing, unexpected or untimed jobs disclose incomplete coverage; only validated intervals become bars. Missing duration is unavailable, while a genuine zero-duration interval remains zero. Browser completion events use original attempt timestamps and duration, preserving flaky retry success, retry failure and incomplete checkpoints. Invalid case timing cannot fabricate replay events. Independently validated browser totals remain visible even when their timing cannot be aligned with a job; report dates before the run or after verification are rejected.

The existing readRunArtifact path retains exact run/attempt/commit validation, byte limits, signed-storage host restrictions, no forwarded GitHub token and bounded report caching. Raw logs, steps, traces and private errors never enter the public envelope. The strict pinned v1 validator/reader remains for the existing explicit historical publication path; it is not broadened to accept scheduled failures.

## Caching, continuity and recovery

One coalesced response reuses verification for at most sixty seconds; failures use a fifteen-second cooldown. Artifact metadata is revalidated before reusing report contents. The browser bounds the combined live/archive envelope to 2.2 MB, uses a twelve-second deadline, cancels on unmount and revalidates on visibility return. A checking label preserves mounted evidence only during bounded refresh; confirmed unavailability removes live evidence.

One small highest-observed completed-nightly identity is persisted through the existing private snapshot facilities. The marker is scoped to repository/branch/workflow and cannot publish evidence, establish success or override revocation. Conditional generations are captured before discovery; monotonic identity checks also reject sequential older writers. Local file storage remains single-process, atomic and private. Cloud storage uses existing bounded SDK operations and snapshot permissions; persistence is awaited inside the active request. Corrupt/denied continuity storage is disclosed and ambiguous older selection fails closed. A missing never-observed/deleted run cannot be reconstructed from this marker; cold starts and snapshot lifecycle limits remain explicit.

Upstream removal, artifact expiry, denied storage and archive corruption/revocation are independent states. No per-night permanent archive collection, automatic publisher or broader archive permissions is introduced. The current v1 archive retains its original identity, dates and integrity/revocation rules.

## Explicit historical archive

`server/test-archive.ts` is separate from the rolling-history snapshot cache. The trusted owner command `npm run archive -- publish` fetches the pinned live source itself and requires usable sanitized case evidence; it cannot import an arbitrary local response. Run it with the publication identity and private archive bucket. Runtime access is read-only and there is no public write endpoint.

Publication writes a SHA-256-addressed immutable envelope, reads and verifies its bytes, then conditionally replaces the scope selection using the generation captured before publication. Concurrent or failed replacements cannot overwrite a newer selection or destroy the last usable archive. Preserve original jobs, timestamps, run/attempt/commit and every case attempt. Object versioning provides owner recovery; no lifecycle rule may expire the retained archive. A digest detects corruption, not malicious activity by an authorized publisher; bucket IAM and reviewed source remain the provenance boundary.

Live nightly status remains visible independently of replay detail. An independently valid archive is labelled **Older archived run** / **Archived historical run**, retaining its original date and identity; it cannot turn a newer failure or unavailable source into a pass. Its 60-second availability verification is not recent GitHub verification. It never enters rolling metrics or latest-run counts. Corrupt or inaccessible archive storage cannot suppress independently valid live job timing. Readers recheck selection generation to detect concurrent replacement/revocation.

Use `npm run archive -- revoke` for a deliberate tombstone; ordinary publication cannot undo it. `npm run archive -- restore` requires a new verified live publication. To restore an older retained version after corruption, an owner must independently verify its envelope/hash/scope, inspect the current generation and deliberately restore the matching selection conditionally. Do not auto-restore a revoked selection. For an oversized unreadable selection, use owner storage tools with the observed generation rather than weakening the reader limits. Removal means revoke first, confirm unavailable fallback after cache expiry, then deliberately remove unneeded object generations; soft-delete recovery lasts for its configured retention. Keep the last verified usable archive until a replacement is durably verified, unless the owner deliberately revokes/removes it.
